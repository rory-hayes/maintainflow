## Status and priority

- **Verified working:** current implementation passed the acceptance test, with evidence in `VERIFICATION.md`.
- **Implemented but unverified:** code exists; its stated acceptance test has not passed yet.
- **Blocked by an external dependency:** independent implementation is complete enough to identify the exact credential, provider, or account action needed.
- **Deferred — reason:** not implemented, with an explicit scope or sequencing reason.
- **P0:** complete authenticated vertical slice and tenant/data safety. **P1:** broader product operations. **P2:** extended parity; retain visible gaps.

The implemented backend is TypeScript/Fastify with local PostgreSQL persistence, migrations 001–008, forced tenant RLS, a durable jobs table, a document lifecycle journal, and private filesystem originals. App feature routes use `/app`, `/app/parsers/:id`, `/app/documents/:id`, `/app/integrations`, `/app/usage`, and `/app/settings`. The actual public/API prefix is `/api`; `/api/v1` is not implemented. External provider adapters remain distinct from real-account verification. Central browser workflows now have direct desktop/tablet/mobile evidence in [BROWSER-QA.md](BROWSER-QA.md); broad combinations and large-tenant coverage remain bounded. Partial rows name both the tested subset and the remaining acceptance gap; required missing engineering is not excused by unavailable credentials.
