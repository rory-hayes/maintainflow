## Findings

### E2E-01 — scanned raw currency is inferred from the account header

**Minor extraction/provenance defect; observed on the deployed provider run.** The preset requires a raw transaction currency to be null when currency is stated only at account level. Both scanned rows returned `EUR`, with evidence pointing to the account header. Native rows correctly left those raw fields null. Wrapped descriptions were preserved with their line break; whitespace differences were allowed by the original test.

All normalized dates, descriptions, references, debit/credit amounts, running balances, account identity, statement period and totals matched the synthetic source. The normalized transaction currency correctly resolves to EUR for both renditions. No amount/date correction was needed in this sample.

The strict run stopped before correction/approval/export. Its failed receipt, raw values and fixtures are preserved. A read-only second retrieval confirmed the mismatch; extraction was not repeated to seek a passing answer. This is not a demonstrated arithmetic failure or a broad accuracy measurement. Review cannot assume raw provider output always follows every literal-field instruction.

### E2E-02 — an export-only API key cannot read exports

**Major functional defect for the advertised API permission; reproduced locally.** Settings permits `exports:read`, but deployed export list/download routes require `results:read`. A valid export-only key receives 403 for its own workspace's saved exports.

The local fix accepts either read scope for listing/downloading saved exports, retaining the existing `results:read` behavior. Creating exports and reading extraction runs/mappings still require `results:read`. Tenant, membership, expiry and revocation checks remain in force. Regression tests use saved CSV, XLSX and JSON bytes and prove denial of unrelated/foreign access. Deployment status is recorded in the final verification below.

### E2E-03 — release records and sign-in copy are stale

**Minor documentation/copy defects.** Tracked launch records still described pre-PR46 source and unapplied migrations. Their new current summaries distinguish completed deployment from retained historical evidence. Sign-in also referred to a separate Parseur account; the local copy now says to use the MaintainFlow account.
