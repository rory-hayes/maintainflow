# Architecture

Decision record, updated 7 September 2026. Internal project: Parseur. Original application identity: Folio.

## Runtime

React, TypeScript, Vite and React Router compose feature-owned screens. Shared design tokens apply to both the public site and application. Fastify provides a same-origin typed API. PostgreSQL 17 stores accounts, memberships, parser configurations, immutable schema versions, document metadata, jobs, extraction runs, corrections, approvals, exports, integrations, usage and audit records. One durable worker claims database jobs transactionally using SKIP LOCKED and leases; it runs independently from the HTTP process.

No managed Supabase capability or project credential is exposed in this task. The reproducible local installation therefore uses the installed PostgreSQL binary, real password authentication in the application, and a private filesystem object-storage adapter. This is a real local platform; it does not establish managed authentication, production hosting, or cloud storage readiness. Production adapters and external verification remain explicit release gates.

## Local isolation

The development database and private files live under ignored `.local/` inside this project. The PostgreSQL Unix socket is inside a user-private directory, with TCP disabled. A restricted application database role uses forced row-level policies with transaction-local workspace context. Worker and migration access is separate. The application binds to loopback by default. Every resource lookup also carries the authenticated workspace identifier. Passwords are scrypt hashes; session and API bearer tokens are stored as hashes. Cookies are HTTP-only, same-site and secure in production. Mutations validate the Origin header for browser sessions. Scoped API keys are revocable.

## Processing contract

Intake validates filename, format signature, byte and page limits before accepting a document. Each upload receives a SHA-256 digest; duplicates are scoped to a parser. The original bytes are kept privately. A queue transaction creates the document and pinned extraction request. Native PDF text, plain text, EML and supported office formats feed deterministic saved text-anchor rules. The implemented OpenAI adapter uses strict schema-constrained Responses requests with the fixed `gpt-5.4-mini-2026-03-17` snapshot and `folio-openai-extraction-v2` prompt. All PDFs send original Base64 bytes as well as decoded text; PNG/JPEG send original image bytes at high detail; other supported formats send decoded text. Requests set `store: false`, expose no tools and treat document content as untrusted data. Secure credential setup is complete. API/worker entrypoints explicitly initialize the provider after configuration loads; `buildApp()` and worker-helper imports stay inert for controlled tests.

Schema versions support nested objects/tables, required fields, explicit defaults, instructions, text transforms, and allowed choices for text fields. An invalid choice or ambiguous numeric text stays reviewable; the engine does not choose a replacement.

Runs preserve document digest, schema version, extraction engine/model, prompt version, source text/page evidence, raw values, normalized values and validation issues. Corrections and approvals are separate immutable events. Approved output is never silently replaced by reprocessing. Missing data stays null; identifiers remain strings. Native evidence is checked against the quoted page after whitespace collapse, including raw-value presence. Image/PDF quotes that cannot be matched to native text are explicitly marked `model-visual` and retain a review warning; they are not independent OCR proof. Coordinates and probability claims are not fabricated. Every successful AI result enters review, and approval validates current schema values. Evidence warnings do not replace human comparison or establish semantic correctness.

AI normalization preserves raw output and source evidence. For CSV only, a bounded helper decodes a scalar when it exactly equals a whole quoted token parsed from the source and is not also an actual decoded cell value. Embedded commas/newlines and escaped quotes remain data; malformed source or exceeded traversal limits returns the raw normalization input unchanged. Calendar-date normalization supports locale-specific unambiguous written months for Gregorian calendars, with invalid dates left for validation; timestamps/timezone conversion remain unsupported. The [AI extraction contract](AI-EXTRACTION.md) records schema/input/output bounds, the 80-second provider and 90-second worker deadlines, safe permanent/retry errors, shutdown cancellation and late-result exclusion. Successful runs retain actual prompt/model/token/cached-token metadata and estimated cost; failed-call charges are not reconciled.

The frontend `ExtractionSources` disclosure walks immutable `rawValues`, the pinned schema and evidence to expose original nested/table quotes and original row numbers. It is separate from corrected, deleted, added or reordered result rows; existing page navigation and model-visual labels are retained. `RunModelUsage` was moved unchanged into its own component. [REVIEW-PROVENANCE.md](REVIEW-PROVENANCE.md) records the display contract, controlled recursive rendering tests and completed desktop/mobile table-source navigation and keyboard checks.

Migration 008 adds a tenant-scoped append-only document journal. Intake records received and queued in one atomic transaction; changed processing states are journaled by a database trigger. Exports record their own phases against the chosen approval without overwriting a newer run's review state. A savepoint rolls back partial export output on handled errors while retaining safe failure history. Exports remain synchronous; an abrupt database/process loss can roll back the whole uncommitted request. [DOCUMENT-LIFECYCLE.md](DOCUMENT-LIFECYCLE.md) defines ordering, API limits, isolation and deletion behavior.

## Exports and integrations

CSV, XLSX and JSON exports are generated server-side from the latest approved snapshot by default; an optional document/approval selection pins a specific historical approval. Saved column mappings and nested line-item flattening apply to CSV/XLSX; JSON preserves nested values and approval/correction identity. Spreadsheet strings that could become formulas are escaped. Export snapshots persist with their input revision. Outbound webhooks use a durable delivery ledger, HMAC signatures, bounded retry, stable delivery identity and explicit replay. Destination validation rejects internal network addresses and redirects. Email intake, Google Sheets and Stripe use separate provider adapters with explicit configuration status; an unconfigured adapter cannot return success or expose a live intake address.

## Operations and acceptance

Usage events have unique idempotency keys. Quota reservations and job claiming are transactional; automatic attempts do not reserve local pages again. Provider requests may still incur retry or failed-call charges outside successful-run estimates. Explicit reprocessing is separately recorded under a documented plan rule. Retention and deletion first lock the document and remove its database-derived copies (runs, corrections, approvals, export snapshots, webhook payloads and Sheets write reservations). The same transaction records original-file removal in the tenant-scoped `file_deletions` queue. Immediate removal normally completes the request; filesystem errors retain a visible pending/failed entry with bounded retries and an admin retry action. Minimal usage/audit identities remain. Existing external exports, email-provider originals, downloaded files and destination spreadsheet copies are outside this local deletion boundary. Intake event tombstones prevent a deleted document from being recreated by a repeated event; reuse of an idempotency key with different content/parser returns a conflict. Audit events retain identifiers and action metadata without document contents or credentials.

Local tests, browser verification, provider-backed extraction, live email, integration accounts, Stripe test mode, deployed revision and customer use are tracked separately in `VERIFICATION.md` and `RELEASE-GATES.md`. No public deployment is part of the initial authorization.

## Workspace capacity and membership auditing

Parser creation and settings changes, including archive/restore, share a transaction-scoped workspace advisory lock. Creation and only an actual archived-to-active transition check the current active count against the stored plan’s parser cap before writing. Ordinary edits remain usable at capacity; failed restores roll back all requested changes and their audit event. The cooperating routes serialize concurrent create/restore attempts; an unrelated plan update or administrative SQL is outside that lock contract.

Invitation acceptance, pending-invitation revocation, accepted-invitation-record deletion, membership role changes and member removal write their audit event in the same transaction as the state change. Events retain actor/entity IDs and bounded role metadata, with no invitation tokens, email/name or credentials in their metadata. Role no-ops and rejected requests create no success event. Removal’s membership deletion, key revocation and workspace-session deletion roll back together if its audit insertion fails. Existing invitation acceptance preserves an existing member’s role. Historical changes receive no fabricated events.

Two parser-capacity cases and five membership-audit cases pass within the **167-test aggregate** and build on the [186-file source](evidence/workspace-integrity-final.json). [WORKSPACE-INTEGRITY.md](WORKSPACE-INTEGRITY.md) records exact focused/full results and coverage limits. The prior AI browser and model evaluation evidence remains intact; extraction and UI code are unchanged.

## Decoder and deployment boundary

The API now decodes original bytes in a fresh subprocess with an allowlisted environment, at most two active children per calling process, a 30-second kill deadline, 192 MiB V8 heap, 10 MiB input, 2 MiB decoded text and 4 MiB response limits. Existing page/image/Office-container bounds remain. This subprocess retains the OS user’s filesystem/network privileges; it is not an OS sandbox and does not cap native RSS or total CPU. Public untrusted uploads still require deployed OS/container identity, filesystem, network and full-resource isolation.

A durable write reservation precedes original-file creation and protects active intake. Worker maintenance reconciles old unreferenced UUID originals under workspace/row locks, using persisted filename/reservation cursors and oldest-serviced-first workspace rotation. It preserves recent, referenced and active-intake files, and eventually removes expired reservations with no file. File removal uses the durable deletion queue. Nine controlled decoder/recovery tests establish these local transitions; directory enumeration remains linear and no crash/load soak is claimed. See [DECODER-RECOVERY.md](DECODER-RECOVERY.md) for exact limits and evidence. Local PostgreSQL/file adapters also require supervised workers, backups/restore proof and persistent storage before deployment.

## AI evidence and current verification boundary

Real synthetic OpenAI results and failures are preserved in [AI-EXTRACTION.md](AI-EXTRACTION.md). The earlier v1 regression measured 74/74 values. A separately authored held-out set measured 49/51, with both misses caused by the same French receipt date including adjacent prose/time. Prompt v2 adds a date-field instruction to select only the literal calendar-date component, preserving spelling/order and excluding file metadata; normalization stays strict. Its unchanged-input regression replay measured 51/51. The replay is not new held-out accuracy evidence. [Current verification](VERIFICATION.md) retains exact source identities, test/build outputs and their historical checkpoints. Fifteen controlled rendering tests cover source disclosure (8), AI availability (4) and cost display (3); these tests make no provider, database or browser calls. After the user unlocked the Mac and explicitly approved the workflow, [AI receipt browser acceptance](AI-BROWSER-ACCEPTANCE.md) completed real creation, upload, worker extraction, source comparison, approval, matching JSON download and persisted reload after a service restart. Desktop/mobile source navigation and keyboard checks also passed after containing a hidden table label that caused mobile overflow. Real Resend/Sheets/Stripe account checks remain pending; those adapters are separate from the verified OpenAI workflow.
